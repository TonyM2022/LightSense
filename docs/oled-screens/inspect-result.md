# 教室巡检结果页 — 设计稿（3 版候选）

> 仅设计稿与草图，**未修改固件代码**。128×64 逐像素绘制，4× 最近邻放大为 512×256；字形全部取自固件同款 U8g2 字库（`wqy12_t_gb2312` / `wqy16_t_gb2312` / `logisoso16_tf`）的真实位图，与 `docs/oled-screens/` 下既有 17 张同一口径。

## 结论（推荐）

**推荐 A 版：单屏「结论徽章 + 5 点结果格」。**

理由：

1. 巡检结束时使用者最需要两件事——「这个教室过没过」「哪个点出问题」，A 版一屏同时给出，且 5 个点位状态按物理位置顺序（C/LF/RF/LB/RB）横排，扫一眼即可定位；B 版只能看到最差点，C 版需要再按一次键。
2. **零交互**：不需要引入翻页状态机、超时计时器或额外按键语义，与现有 `drawAll()` 的 1.024 s 重绘天然兼容，改动面最小。
3. **零新增字体**：只用已链接的 `wqy12` + `wqy16`；C 版汇总屏的 A/B/C 大字若用 `logisoso16`，也已随开机 logo 进入固件（若未落地则 +3,048 B）。
4. 屏上 23×26 的格子留有边框，异常格可用反白（C 版做法）进一步强化，信息层级清晰。

B 版适合「只看结论」的极简场景；C 版留作后续扩展（A 版 + 一屏逐点明细），本次不作为首选。

## 一、字段可得性（以 `src/classroom.h` / `classroom.cpp` / `oled.cpp` 为准）

### 表 1：结果页所需字段

| 字段 | 可得性 | 来源 / 接口 | 说明 |
| --- | --- | --- | --- |
| 教室号 / 流水号 | ✅ | `InspectionTask.room`（24 B） | OLED 自动巡检固定 `Z%03u`（Z001 起），`classroom.cpp` 建任务时写入 |
| 内部任务号 | ✅ | `InspectionTask.id` | 自增 1..；屏上没必要显示，用 room 即可 |
| 已完成点数 / 总点数 | ✅ | `pointsCount`、`CLS_PT_COUNT=5`、`mask` | 每点完成即刷新并落盘（`classroom.cpp:318-322`） |
| 汇总结论 A/B/C | ✅ | `InspectionTask.verdict`（`CLS_SUM_*`） | `classroomInspectFinish()` 已写入并落盘（`classroom.cpp:486-490`） |
| 合规 / 异常点数 | ✅ | `ClassroomSummary.passCnt / failCnt` | 每点完成即刷新（`classroom.cpp:323-325`），也可结果页现算 |
| 过暗 / 过亮点数 | ✅ | `ClassroomSummary.darkCnt / brightCnt` | 同上 |
| Pst / SVM 超标点数 | ✅ | `ClassroomSummary.pstFailCnt / svmFailCnt` | 同上 |
| 最差点位 | ✅ | `ClassroomSummary.worstCode` + `classroomPointCode/Name()` | 0 = 无异常 |
| 逐点判定 | ✅ | `ClassroomRecord.verdict`（`FV_*`），按 `taskId + pointCode` 归组 | 每点取最后一条记录（复测只保留末次） |
| 逐点 Pst / SVM / 波动深度 / 频率 / ADC | ✅ | `record.pstMean / svmMean / mMean / freqHz / vavgMean` | 已在 `ClassroomRecord` 内，小题可直读 |
| 每点测量时长档 | ✅（可反推） | `record.windows` × 1.024 s | 30 s / 1 min / 10 min 三档，屏上一般不必显示 |
| 巡检场景 / 巡检人 | △ | `InspectionTask.scene / inspector` | 字段存在；但 OLED 自动建任务固定 `"OLED"` / `""`（`classroom.cpp:450`），屏上价值低 |
| 任务创建时刻 | △ | `InspectionTask` epoch | OLED 路径传 0（`classroom.cpp:422`），不可靠 |
| 绝对日期 / 时刻 | ❌ | — | 设备无本地时区格式化封装；`record.ts` 是开机秒数，`record.epoch` 可能为 0。屏幕上画「09:41」这类时间是取不到的数据，**不画** |
| 巡检总耗时 / 起止时间 | ❌ | — | 任务与记录都没有「结束时刻」字段，无法算总时长 |
| 逐点建议文案 | ❌ | `ClassroomSummary.advice` 只是 `CLS_ADV_*` 位掩码 | 设备端没有对应短文案表，只有网页端渲染 |
| 每点复测次数 | ❌ | — | 记录按点位取末条，历史复测条目不计数 |
| 长教室号 | ⚠️ | `room[24]` 截断 | 网页端可建长教室号；屏上必须 `fitUTF8()` 截尾，防 128 px 溢出绕回左端 |

### 「需新增存储 / 计算」的代价（如确实需要）

| 需求 | 新增存储 | 计算 / 代码 | 建议 |
| --- | --- | --- | --- |
| 巡检起止时间、总耗时 | `InspectionTask` +4 B（结束 epoch），NVS 多写 1 次 | 约 10 行 | 价值低，不建议 |
| 逐点建议短文案 | 0 | 约 20 行 `advice` → 短句映射 | 可做，但 5 点格子放不下，只在明细屏可考虑 |
| 每点复测次数 | 0 | 汇总时线性扫描并计数（O(n)） | 不建议（信息价值低） |
| 屏上显示日期时间 | 0 | `time.h` + 时区常量 + NTP 就绪判断，Flash +数百 B | 不建议 |

结论：**A/B/C 三版都只使用「已可得」字段，草图里没有任何取不到的数据。**

## 三、交互与时序（设计层面，不写代码）

| 项 | 设计 |
| --- | --- |
| 触发点 | `oled.cpp:413` — `classroomInspectNextPoint()` 返回 0（5/5）时调用 `classroomInspectFinish()`，成功后进入结果页 |
| 首帧时机 | 同一次按键处理末尾 `drawAll(flickerSnapshot())`（`oled.cpp:444`）立即整帧重绘，按键响应 ≈0.2 s，与现有按键路径一致 |
| 停留时长 | **不设超时，任意键退出**。理由：设备端没有「历史结果」入口，超时消失后结果不可再查；如需极简可设 15 s，但会牺牲可回看性 |
| 是否被 1.024 s 报告窗口覆写 | **不会**。结果页必须是 `drawAll()` 的一个状态分支（与 `s_page` 同级的瞬态态），`oledShow()` 每个窗口重复绘制同一状态；不能用「一次性覆盖层」写法（那种写法会在 ≤1.024 s 内被正式页面冲掉） |
| 按键映射 | LEFT/RIGHT：退出结果页并保留原「切页」意图；UP/DOWN/OK：退出并回教室页第 1 步。结果页期间不产生测量动作 |
| 与「回第 1 步菜单」的衔接 | 退出时 `s_clsStage = 0`（与 `oled.cpp:378/382/424` 既有做法一致），菜单回到「第 1 步选模式」 |
| 是否需要改 `classroomInspectFinish()` 调用顺序 | **不需要**。`finish()` 内部把 `inspCur = -1`（`classroom.cpp:496`），但任务仍在 `tasks[]` 且 `status=INSP_ST_DONE`、`verdict` 已落盘。oled 侧只要在调用 `finish()` **之前**用 `classroomInspectTaskId()` 记住 id（`classroom.cpp:506-508`），或调用后用 `classroomTasks()` 找最后一个 DONE 任务即可，两种方式都是只读，不改 `classroom.cpp` 语义 |
| 数据获取成本 | `classroomSummarize(id, &sum)` 实时扫描 RAM 中的记录表（最多 `CLS_MAX_RECORDS` 条），只读、不写 NVS；`ClassroomSummary` 约 20 B，栈上分配 |
| 未测全场景 | OLED 路径只在 5/5 时可结束；网页端可能提前 finish → 结果页显示「未测全 n/5」，结论兜底 `--` |
| 主循环影响 | 无 `delay()`；绘制量同普通页（图元 < 300 px + 文本），远小于 SW I2C 整帧 40–80 ms |

## 四、落地成本

| 项 | A 版 | B 版 | C 版 |
| --- | --- | --- | --- |
| 新增字体 | **0 B**（`wqy12` + `wqy16` 已在用） | `logisoso16_tf`：若开机 logo 已落地则 **0 B**，否则 +3,048 B | 同 A（若用大字则同 B） |
| 新增 NVS 存储 | 0 | 0 | 0 |
| 堆分配 | **0**（无 `new`/`malloc`，无常驻缓冲） | 0 | 0 |
| RAM | ≈ +6 B（结果页 taskId / 阶段 / 时间戳） | 同 A | ≈ +8 B（多一个屏序号） |
| Flash（代码） | 约 +250–500 B（≈60–100 行绘制代码） | 同量级 | 约 +400–700 B（两屏 + 翻页） |
| 对 Web 汇总 / CSV | 无影响 | 无影响 | 无影响 |

- 结果页只读现有任务/记录结构，`verdict` 早已在 `classroomInspectFinish()` 落盘，故 Web 页面与 CSV 导出不受任何影响。
- 若后续加「屏上日期」「总耗时」才需要动 NVS 结构，本设计不涉及。
- 所有绘制复用 `u8g2` 现有 1 KB 全缓冲与同一刷屏路径，不另开 I2C、不另开缓冲。

### 防溢出校验

- 所有文本按真实字模 advance 宽度计算并居中/右对齐；C 版第 2 屏最右墨迹 x=118，A 版格子右缘 x=126，均 <128，**不会出现右侧包绕回左端**。
- 每个点位的判定使用单字（合/超/双/暗/亮/免/-），宽 12–24 px，23 px 格内不溢出；明细屏「双超」列宽 24 px，与 Pst 列间隔 4 px。
- 中文点名列宽度固定 24 px（2 个 CJK 字），与判定列之间留 4 px。
